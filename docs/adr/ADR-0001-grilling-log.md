# ADR-0001 · Grilling 记录 (Interview Log)

> 本 ADR 是 Grilling 会话的持续日志：每一轮拷问的问题、用户回答、以及由此得出的设计决策。决策变更时追加新条目，不覆盖历史。

## 状态: 进行中

## 用户原始需求摘要
- macOS 应用（兼容 ≥13）
- 置顶在所有应用上的文本提醒（单行 / 多行列表）
- 自由多行文本，一个大文本框
- 不影响操作（点击穿透）
- 仅背景透明，文字保持清晰
- 可编辑 + 可设透明度
- 菜单栏图标 → 控制面板（切换编辑 + 透明度滑块）
- 全局热键 ⌥⌘E 切换编辑/穿透（需授权）

## 第 1 轮 · 平台选型与状态机

### Q1 · 技术栈
- **决策 D-001**：采用 **Tauri**（非原生 Swift/AppKit）。
- **griller 标注的风险 R-001**：macOS 上"背景完全透明 + 文字保持不透明 + 鼠标穿透"三者在 Tauri/Webview 层的组合需要验证。Tauri 窗口透明（`transparent: true`）+ `decorations: false` 可行；鼠标穿透在 Tauri v2 可通过 `set_ignore_cursor_events(true)` 实现。但"仅背景透明、文字不透明"需要前端用半透明背景色 + 不透明文字，而非整窗 alpha——这点要在第 2 轮拷问中明确。
- **约束 C-001**：目标平台仅 macOS ≥13，不考虑跨平台（Tauri 跨平台能力在此项目中不使用）。

### Q2 · 编辑态/穿透态状态机
- **决策 D-002**：采用方案 A——两个互斥状态，切换时**同时**翻转鼠标穿透 + 键盘焦点。
  - 编辑态：`ignoresMouseEvents=false`，`NSTextView`/前端 textarea 获焦，键盘输入文字。
  - 穿透态：`ignoresMouseEvents=true`，键盘焦点交还下层 App。
- **待明确 T-001**：Tauri 下"键盘焦点交还下层 App"的具体实现路径——Tauri 窗口在穿透态是否需要 `hide()`+`show()` 才能释放键盘焦点，还是 `set_ignore_cursor_events` 足矣？需在第 4 轮验证。

### Q3 · 全局热键
- **决策 D-003**：默认 ⌥⌘E，允许在控制面板自定义。
- **约束 C-002**：需在设置面板提供热键修改入口，且存储用户自定义热键。
- **待明确 T-002**：Tauri 全局热键插件（`tauri-plugin-global-shortcut`）在 macOS 上的权限模型与授权引导流程。

## 第 2 轮 · 透明实现 / 持久化 / 外观 / 窗口行为

### Q1 · "仅背景透明"实现路径
- **决策 D-004**：采用方案 A——Tauri 窗口 `transparent: true`，前端用 `background-color: rgba(0,0,0,α)` 控制背景透明度，文字 `color` 始终 `alpha=1` 保持不透明。
- **约束 C-003**：透明度滑块只改背景 rgba 的 α 值，不调用 `set_window_alpha`。α=0 时背景完全透明、文字清晰。
- **否决 N-001**：窗口层 alpha（整窗变淡）不符合需求，永久否决。

### Q2 · 文本持久化
- **决策 D-005**：单实例，内容持久化到本地文件（`app_data_dir/n-top/content.json`）。重启自动恢复文本内容。
- **约束 C-004**：不做多实例/多浮层窗口。单一浮层窗口。
- **待明确 T-003**：是否需要持久化"上次窗口位置"——见 Q4 决策，已合并。

### Q3 · 文字外观
- **决策 D-006**：透明度 + 字号 + 字体颜色可配（方案 B）。
- **约束 C-005**：外观参数（背景透明度 α、字号、字体颜色）同样持久化到 `content.json` 或独立的 `settings.json`。
- **否决 N-002**：不做完整富文本（粗体/列表/颜色混合），保持纯文本 + 全局样式。

### Q4 · 窗口尺寸与定位
- **决策 D-007**：固定大小，可拖拽移动，记住上次位置。不做缩放。
- **约束 C-006**：窗口位置（x, y）持久化，重启恢复上次位置。
- **约束 C-007**：窗口尺寸硬编码默认值（后续可放配置，但 v1 不暴露缩放 UI）。

## 第 3 轮 · 菜单栏 / 控制面板 / 多显示器 / 权限引导

### Q1 · 菜单栏图标实现
- **决策 D-008**：采用 Tauri tray 插件（`tauri-plugin-tray`），不写原生 Swift NSStatusItem 桥接。
- **约束 C-008**：tray 图标点击事件在 Rust/JS 层处理，用于触发控制面板弹出。

### Q2 · 控制面板弹出方式
- **决策 D-009**：点击 tray 图标 → 弹出独立小窗口（WebviewWindow）作为控制面板，anchor 到 tray 图标位置附近。
- **约束 C-009**：控制面板窗口含以下控件：切换可编辑按钮、透明度滑块、字号设置、字体颜色设置、全局热键设置。
- **否决 N-003**：原生下拉菜单（`Menu`）无法承载滑块控件，不采用。

### Q3 · 多显示器 / 全屏 Space 行为
- **决策 D-010**：浮层始终显示在所有 Space/显示器最上层。Tauri 窗口设 `always_on_top: true` + `all_workspaces: true`。
- **约束 C-010**：多显示器下，浮层跟随窗口所在显示器（即用户拖到哪个显示器，就显示在哪个显示器上）。不实现"每个显示器各自独立浮层"。
- **约束 C-011**：全屏 App 时浮层仍置顶可见（符合"置顶提醒"用途）。

### Q4 · 全局热键权限引导
- **决策 D-011**：首次启动时检测权限状态，未授权则弹出引导窗口，含"打开系统设置"按钮（跳转 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`）。
- **约束 C-012**：App 持续检测权限状态，授权后自动关闭引导窗口。
- **约束 C-013**：引导窗口内容需说明为何需要权限（注册全局热键 ⌥⌘E）、授权步骤。

## 第 4 轮 · 分发安装 / 签名公证 / 自动更新 / 非目标

### Q1 · 分发方式
- **决策 D-012**：DMG 直接下载 + Homebrew tap（`brew install --cask`）。不上 App Store。
- **约束 C-014**：自建 GitHub Release 托管 DMG；自建 Homebrew tap 仓库提供 Cask formula。

### Q2 · 代码签名与公证
- **决策 D-013**：v1 不做 Apple 代码签名与公证（无 Apple Developer 账号）。
- **约束 C-015**：首次安装触发 Gatekeeper 拦截，用户需"右键 → 打开"或"系统设置 → 隐私与安全性 → 仍要打开"绕过。
- **约束 C-016**：README / 下载页需明确说明 Gatekeeper 绕过步骤。
- **待明确 T-004**：后续若获取 Developer 账号，补充签名 + 公证流程（作为 v1.1 增量）。

### Q3 · 自动更新
- **决策 D-014**：集成 `tauri-plugin-updater` 做自动更新。
- **澄清 CL-001**：`tauri-plugin-updater` 使用 **Tauri 自有签名密钥**（`tauri signer generate` 生成密钥对，私钥签发更新包，公钥嵌入 App 验证），与 Apple 代码签名/公证独立。因此**无 Apple Developer 账号也可实现自动更新**。
- **约束 C-017**：需生成并妥善保管 Tauri updater 签名密钥对；公钥写入 `tauri.conf.json`，私钥仅 CI/发布环境持有。
- **约束 C-018**：更新源托管在 GitHub Release（与 DMG 同源），updater 配置指向 release assets 的 latest.json。

### Q4 · 非目标边界
- **决策 D-015**：以下为**永久非目标**（v1 不做，v2 也不做）：
  - ❌ 多实例 / 多浮层窗口
  - ❌ 窗口缩放
  - ❌ 富文本（粗体 / 列表混排 / 行内颜色）
  - ❌ 跨平台（仅 macOS）
  - ❌ App Store 上架
  - ❌ 云同步 / 多设备
- **注意**：自动更新原列在非目标候选中，用户明确移出——**自动更新是 v1 功能**。
